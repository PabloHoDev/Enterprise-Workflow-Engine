# ADR-003 — Stack Tecnológica

* **Status:** Accepted
* **Date:** 2026-10-02
* **Decision Type:** Technology
* **Related:** `docs/Stack_Consolidada/Stack_Consolidada.md`, `docs/architecture/DEPLOYMENT.md`

---

## 1. Context

A FASE 07 (Technical Foundation) exige fixar a stack que sustenta a implementação. A stack consolidada
já havia sido esboçada; este ADR a formaliza com as versões efetivamente adotadas e validadas.

---

## 2. Decision

| Área           | Escolha                                                         |
| -------------- | --------------------------------------------------------------- |
| Linguagem      | Java 25 (LTS)                                                   |
| Framework      | Spring Boot 4.1.x (Spring Framework 7, Jackson 3)               |
| Segurança      | Spring Security 7.1.x                                           |
| Persistência   | Spring Data JPA + Hibernate 7, PostgreSQL 18                    |
| Migrations     | Flyway (SQL versionado em `src/main/resources/db/migration`)    |
| Build          | Maven + Maven Wrapper (`only-script`, sem binário no repositório) |
| Testes         | JUnit, AssertJ, Spring MockMvc, Testcontainers, ArchUnit        |
| Cobertura      | JaCoCo, com mínimo de 80% de linhas em CI                       |
| API            | OpenAPI via springdoc                                           |
| Observabilidade| Spring Boot Actuator (health, probes, métricas)                 |
| Empacotamento  | Docker (multi-stage, jar em camadas)                            |
| CI             | GitHub Actions                                                  |

Detalhes relevantes:

- o `pom.xml` compila com `--release 25`, de modo que o bytecode é Java 25 mesmo quando o JDK instalado
  é mais novo;
- virtual threads estão habilitadas (`spring.threads.virtual.enabled`), pois a carga é dominada por I/O
  de banco;
- o Hibernate apenas **valida** o schema (`ddl-auto: validate`); a estrutura é propriedade do Flyway.

---

## 3. Alternatives Considered

- **Java 21:** LTS anterior, constava no `pom.xml` inicial. Rejeitado em favor do LTS corrente (25),
  já definido na stack consolidada.
- **Gradle:** build mais flexível, porém Maven é o padrão mais difundido no ecossistema corporativo Java
  e suficiente para um único módulo.
- **Liquibase:** equivalente funcional ao Flyway; SQL puro versionado foi preferido pela transparência.
- **H2 nos testes:** mais rápido, mas diverge do PostgreSQL (jsonb, constraints adiáveis). Os testes de
  integração usam PostgreSQL real.

---

## 4. Consequences

### Positivas

- stack atual, suportada e coerente com o objetivo de demonstrar práticas enterprise;
- o mesmo banco em desenvolvimento, teste e produção.

### Negativas

- os testes de integração exigem Docker (ou um PostgreSQL externo — ver `docs/quality/TEST_STRATEGY.md`);
- versões recentes de framework exigem acompanhamento de atualizações.
